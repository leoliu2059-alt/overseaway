## stripe 测试续费逻辑小技巧
- 链接：http://mp.weixin.qq.com/s?__biz=MzkzNzYzNzE3Mg%3D%3D&mid=2247484539&idx=1&sn=6c559780d8d1280dbcb83692e232cb87&chksm=c28d2020f5faa9360d3d721689d1d14882f93caff289fce4362c5f521deaa828286720ffb8fe#rd
- 详情：文章分享了一个低成本测试 Stripe 订阅自动续费逻辑的技巧。背景是作者发现某用户自动续费成功后，网站侧的积分却没有到账，修复后需要验证「续费事件触发→积分发放」这条链路，但真实月付/年付周期太长难以等待。关键做法是：在 Stripe 后台创建一个「周期为一天」的测试订阅，第二天观察自动续费时积分是否正常到账，从而快速验证逻辑。若发现是 Webhook 事件处理失败，可直接在 Stripe 开发者后台的 Webhooks 页面手动点击「重试（retry）」重新推送事件，无需重新发起支付。该方法的本质是缩短订阅周期来模拟续费场景，配合 Webhook 重试机制定位积分未到账的根因（通常是 `invoice.paid` / `checkout.session.completed` 等事件回调逻辑缺失或失败）。适合独立开发者在初期上线订阅功能时，用最小成本验证续费与权益发放闭环。

## 重大 Next.js 漏洞问题，小心账单爆炸
- 链接：http://mp.weixin.qq.com/s?__biz=MzkzNzYzNzE3Mg%3D%3D&mid=2247484584&idx=1&sn=42b4674d57f0e684283013c897fd29f0&chksm=c28d20f3f5faa9e5eac9116e436e92a4c57147f857533d7dbd53d5960fe415f0c2918ecfded6#rd
- 详情：文章警示 Next.js 曝出的高危漏洞 CVE-2025-66478——未经鉴权即可远程执行代码（RCE）。作者所在社群多人中招：有的网站被加密勒索，有的被远程植入挖矿程序；作者自查 Vercel 项目也发现一个低流量网站的 CPU 占用异常飙升但访客数未变，险些引发账单爆炸。排查路径：Vercel 控制台顶部会标记「异常项目」，点击即可看到受影响项目列表。修复方式是升级依赖版本——作者原环境为 React 19.0.0 + Next.js 15.2.1，经 AI 建议升级到 Next.js 15.2.6 与 React 19.0.1，改动很小。重点提醒：该漏洞可被攻击者利用服务器算力挖矿或加密文件，进而推高 Vercel 按用量计费的 CPU/带宽账单，必须尽快升级 next 与 react 版本并复核部署环境。

## 创建一个 claude skill 减少重复操作

- 详情：文章讲解如何用 Skill Creator 把「用 Nano Banana 生成网页所需图片」这类重复性工作交给 Claude Code 自动完成。常规流程：在 claude.ai 头像→Settings→Capabilities→Skills 中开启 Skill Creator，再让 Claude Code 调用它创建 skill；但作者使用「拼车」账号被禁止访问官网会报错，于是改为手动从 GitHub 下载 Skill Creator 放到用户主目录的 `.claude/skills/` 文件夹（目录不确定可让 Claude Code 查）。创建时用一句话描述需求，例如「创建一个生成图片的 skill，需调用我自己的 API，文档为 d:\code\mksaas-template\docs\nano-api.md」，并把 API 调用文档（如 kie 文档）一并交给它。Skill Creator 会交互式提问，完成后在 skills 文件夹生成新 skill。实测作者只需一句「帮我新增一个 photo to video landing page，feature 图片用 nano-image-generator skill 生成」，Claude Code 就能自动产出带图的页面。

## Google One Tap 丝滑登录
- 链接：http://mp.weixin.qq.com/s?__biz=MzkzNzYzNzE3Mg%3D%3D&mid=2247484873&idx=1&sn=fd495bd25593f091274c829501f5cfd2&chksm=c28d2192f5faa88456268548c4b5f212c6bb3d805ad6241cd68f2a3f90a1cff359392ed05952#rd
- 详情：文章介绍 Google One Tap 登录——用户打开网站后右上角弹出小卡片，无需跳转、无需输密码，一键用 Google 账号登录。该能力由 Google 官方提供，作者直接让 AI 执行「在首页接入 Google One Tap 登录」即自动实现。关键点：他是基于已有 Google 登录扩展的，现成的 Client ID 直接复用；需要特别注意的是，必须在 Google Cloud 后台把网站的 URL 配置到「已获授权的 JavaScript 来源（Authorized JavaScript origins）」列表中，否则 One Tap 弹窗会因来源未授权而无法工作。整体接入成本低，主要工作量在 Google Cloud Console 的来源白名单配置，适合想提升注册转化率的出海网站快速加上无感登录。

## Stripe 重复接入新网站
- 链接：http://mp.weixin.qq.com/s?__biz=MzkzNzYzNzE3Mg%3D%3D&mid=2247485224&idx=1&sn=e6464715e73e6f363d713aedb1aad25d&chksm=c28d2373f5faaa6506eaf80f02ec7ed250172d5a19674baa781131405273392d7e7ce52255cb#rd
- 详情：文章讲解已有 Stripe 账号后，新网站接入的两种主流方式——新建产品与新建账号（新建组织未展开）。方式一「新建产品」：在产品目录配置新产品名称、价格、收费方式；在 Webhooks 新增接收端，筛选要监听的事件并填入新 Webhook 名称与 URL；复制 API 密钥和价格 ID 配置到网站。方式二「新建账号」：点击左上角账号→创建→创建账户→选「创建单独的账户」，流程同 Stripe 标准注册；创建商家时直接选已存在的商家主体，最后把网站的 URL 与账单描述符（statement descriptor）改为新站信息，再走一遍产品配置。优缺点对比：新建产品共用一个 Stripe，配置简单、资金集中，但用户侧显示的网站信息可能串站，且一个站出问题会连带其他站；新建账号配置繁琐、资金分散，但各站支付信息独立、风险隔离更好。

## 如何制作网站的 OG 图
- 链接：http://mp.weixin.qq.com/s?__biz=MzkzNzYzNzE3Mg%3D%3D&mid=2247485345&idx=1&sn=0d735fba47fadd17babb874102b56870&chksm=c28d23faf5faaaec83873b9e8a824605067407f6db6a31a7f850131b5ad96389e93854a8df1d#rd
- 详情：文章分享三种制作 OG 图（社交分享卡片图）的方法，适用外链提交、Google 广告、社媒分享。方法一：用 Nano Banana Pro，提供 logo 和网站截图并套用一段详细的 16:9 横向布局提示词（左区放 logo+3-6 词大标题、右区放悬浮圆角产品面板、强留白、扁平风格、无人物无边框无水印），效果最佳。方法二：用 Google Stitch（stitch.withgoogle.com），右下角选「网址」并上传网站截图，让其生成 16:9 的 OG 图。方法三：用 imgsrc.io 生成器，顶部选目标、上传 TAG/Title/logo/网站截图、选主色即可，但免费版右下角带水印需付费去除。核心是 OG 图比直接截图更利于传播和点击，应专门制作而非随手截图。

## clarity API 获取分析网站数据
- 链接：http://mp.weixin.qq.com/s?__biz=MzkzNzYzNzE3Mg%3D%3D&mid=2247485479&idx=1&sn=cf350210109c1455e7dfa5b891cf4716&chksm=c28d2c7cf5faa56a938fc1b9325be333b82450f6fa9c98051d15a912420859a9a525aaf12550#rd
- 详情：文章分享用 Microsoft Clarity 的 Data Export API 把后台数据自动拉取下来，转存到自己的数据库或本地结合 AI 做每日用户行为分析，省去人工看录屏。步骤：在 Clarity 后台 Settings → Data Export 生成一个 API Token（仅显示一次，需妥善保存）；参考官方文档的 curl 示例，把 token 替换为自己的，再让 AI 调用拿数据。示例接口：`curl 'https://www.clarity.ms/export-data/api/v1/project-live-insights?numOfDays=1&dimension1=OS' -H 'Authorization: Bearer YOUR_TOKEN'`。参数 numOfDays（1-3 天）配合 dimension1/2/3 做维度拆分（如 OS）。限制：每个项目每天仅可调用 10 次，仅能获取最近 3 天数据，单次最多返回 1000 条。文档地址 learn.microsoft.com/en-us/clarity/setup-and-installation/clarity-data-export-api。

## 分享遇到的 3 个 vercel 账单暴涨的问题

- 详情：文章复盘三次 Vercel 账单暴涨及解法。1）图片资源导致：游戏攻略站把大量图片放项目内上传 Vercel，并触发 Vercel Image Optimization，花费爆炸；解决是把资源迁到 Cloudflare R2（免费 10G，超出 $0.015/GB/月）。2）爬虫导致：两个低流量站日账单飙升，排查发现几个 IP 每秒疯狂访问（一小时上千次），在 Vercel 自定义规则（Custom Rule）直接 deny 这些 IP。3）未命中缓存导致：群友上线「登录记录国家码」功能后页面不走缓存，Cloudflare 视为动态请求持续打到 Vercel 的 Fast Data Transfer/Origin Transfer，需在 Cloudflare 配置缓存。补充提醒：后端阻塞式调用生图等三方 API 导致服务器空转、CPU 升高的也会推高账单，需日常监控。
